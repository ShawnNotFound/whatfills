What you can do
  1. Docker images, containers and build cache: 8.3 GiB in /var/lib/docker
     Do not delete by hand. Use the suggested command or the program that owns it.
     Everything Docker stores: images, containers, volumes and the build cache. Images and build
     cache pile up as you pull and build, and stopped containers and unused volumes stay until
     removed. Deleting files here by hand breaks Docker.
       $ sudo docker system df
         See what Docker is using
       $ sudo docker system prune
         Remove stopped containers, unused networks, dangling images and build cache
       $ sudo docker builder prune
         Remove the build cache only
     Tip: Docker can keep its data on a bigger disk: set "data-root" in /etc/docker/daemon.json and
     restart Docker.
  2. Hugging Face models and datasets: 6.2 GiB in /home/alex/.cache/huggingface
     Safe to delete. It is rebuilt or downloaded again when needed, which takes time.
     Models and datasets downloaded by Hugging Face libraries (transformers, diffusers, datasets,
     huggingface_hub). Anything deleted is downloaded again the next time it is used.
       $ huggingface-cli scan-cache
         List cached models with their sizes
       $ huggingface-cli delete-cache
         Pick cached models to delete
     Tip: Keep the cache on a bigger disk: add export HF_HOME=/path/on/big/disk/huggingface to your
     shell profile.
  3. systemd journal (system logs): 4.0 GiB in /var/log/journal
     Safe to delete. It is a cache or a leftover, and nothing you need is lost.
     Logs collected by systemd-journald. Unless a limit is set, the journal may use up to 10% of the
     filesystem, capped at 4 GiB. Shrinking it removes the oldest entries first.
       $ sudo journalctl --vacuum-size=500M
         Shrink the journal to 500 MB
       $ sudo journalctl --disk-usage
         Show how much the journal uses
     Tip: To cap it for good, set SystemMaxUse=500M in /etc/systemd/journald.conf (or in a file
     under /etc/systemd/journald.conf.d/), then run: sudo systemctl restart systemd-journald
  4. Docker container logs: 3.3 GiB in 2 files, biggest
     /var/lib/docker/containers/14c2529e…/14c2529e…-json.log

     size limit these logs keep growing for as long as the container exists.
     Tip: Limit container logs in /etc/docker/daemon.json: "log-opts": {"max-size": "50m",
     "max-file": "3"}. This applies to containers created afterwards.
